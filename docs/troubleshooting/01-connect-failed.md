# 连不上设备？七步排查法

现场 90% 的"采集失败"是网络/参数问题，不是协议问题。按这个顺序排查，别乱猜。

## 1. ping 得通吗？

```
ping 192.168.1.10
```

不通 → 检查网线/交换机/IP 段。网关机器常常要手动配静态 IP（和设备同段）。

## 2. 端口开了吗？

```
# Modbus TCP / OPC UA / S7 / MC / FINS 的端口
502   4840   102   5000   9600
```

用 `Test-NetConnection 192.168.1.10 -Port 502`（PowerShell）。通了说明设备的协议服务开着。

## 3. 协议选对了吗？

- 设备手册说 Modbus TCP？→ 模式选 `tcp`
- 经串口服务器？→ `rtu-over-tcp`（帧格式不同！）
- 直接 485？→ `rtu` + 串口参数（**9600 8 N 1** 最常见，错一个都连不上）

## 4. 从站号对吗？

Modbus 报文里的 unit id 必须等于设备设置的站号（常见 1）。RS485 总线上多台设备站号不能重复。

## 5. 地址对吗？

- `40001` 是"第 1 个保持寄存器"不是"偏移 40001"
- 怀疑错位：把地址 ±1 各试一次，看数值是否对上量级
- 32 位浮点乱码 → 通道参数切"字交换序(CDAB)"

## 6. 设备本身限制

- S7-1500 默认禁止 PUT/GET；优化 DB 没关
- 西门子连接数满（拔掉编程软件试试）
- 三菱 FX 的 MC 帧格式是 FX 专用变体
- 设备白名单功能只允许指定 IP 访问

## 7. 看报文

打开通道的报文日志（或 Wireshark 抓包），对照协议教程：

- **发出去了没有响应** → 前面 1-6 的问题
- **有响应但报异常码** → 看《Modbus 功能码》异常码表
- **响应 CRC 错** → 串口干扰/波特率错

> 💡 记住一个原则：**先通网络，再通协议，最后谈数据**。
