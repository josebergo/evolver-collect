# TCP MBAP 与 RTU 帧（含 CRC）

同一套 PDU（功能码+数据），两种外衣。

## Modbus TCP：MBAP 头 7 字节

```
00 01 | 00 00 | 00 06 | 01 | 03 0000 0002
事务号   协议号    长度   从站   ─── PDU ───
```

| 字段 | 说明 |
|---|---|
| 事务号 | 2 字节，响应原样带回——**并发请求的配对凭据** |
| 协议号 | 恒 0000 |
| 长度 | 从"长度"字段之后到帧尾的字节数 |
| 从站号 | 兼容串口时代的站号 |

本项目驱动严格校验事务号与从站号，防止串口服务器把别的响应喂进来。

## Modbus RTU：CRC16 收尾

```
01 03 0000 0002 C4 0B
站 功能 起始 数量  CRC↓
```

- CRC-16/Modbus：多项式 `0xA001`、初值 `0xFFFF`、**低字节在前**
- 帧定界：靠 3.5 字符时间的静默（串口环境）；本驱动按功能码推算响应长度实现读全帧

**手算 CRC 没必要，但要会验证**：用工具（如串口助手）发 `010300000002`，响应尾应是 `C40B`。本项目的单元测试里就有这个向量。

## RTU over TCP

串口服务器（MOXA 等）把 RTU 帧原样透传成 TCP——帧还是 RTU 的（带 CRC），但走网口。本系统通道参数选"rtu-over-tcp"即可。无硬件时的教学/测试也用它。

## 三种模式怎么选

| 现场情况 | 模式 |
|---|---|
| 设备直接提供网口、手册说 Modbus TCP | `tcp` |
| 485 串口经串口服务器上网 | `rtu-over-tcp` |
| 网关机器直接插 485 转 USB | `rtu`（配 COM 口/波特率） |

串口参数（9600 8 N 1 最常见）必须和设备一致，错一个就连不上——见排障手册。
